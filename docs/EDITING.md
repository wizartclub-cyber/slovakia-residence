# Як міняти тексти й дані без розробника

Усе, що видно на сайті, лежить у звичайних текстових файлах. Їх можна відкрити
в будь-якому редакторі (навіть у TextEdit) і виправити. Після правки одна
команда перевірить, чи все гаразд.

## Перед початком — одна команда

```
cd ~/Documents/Codex/slovakia-residence
pnpm validate
```

Вона каже або `✓` тричі, або показує, що саме не так і в якому файлі. Поки
вона не зелена, сайт не збереться — це навмисно.

Побачити зміни в браузері: `pnpm dev`, далі відкрити
http://localhost:5173/slovakia-residence/

## Де що лежить

| Що хочу змінити | Файл |
|---|---|
| Назви пунктів меню, кнопки, підписи | `src/locales/uk/common.json` і `src/locales/sk/common.json` |
| Порядок пунктів меню, які сторінки існують | `content/ui/site.yaml` |
| Питання опитувальника і варіанти відповіді | `content/ui/finder.yaml` + підписи в локалях |
| Дата «стан права» на всіх сторінках | `content/ui/site.yaml`, розділ `legalBaseline` |
| Текст маршруту: кроки, строки, застереження | `content/procedures/<назва>.yaml` |
| Документи: назви, пояснення, строки давності | `content/documents/<назва>.yaml` |
| Збори і звільнення від них | `content/fees/*.yaml` |
| Органи | `content/authorities/*.yaml` |
| Спільні розділи (підстави для відмови тощо) | `content/notes/*.yaml` |
| Список джерел | `document-registry-v0.4.yaml`, далі `pnpm sources:build` |

**Не редагувати руками:** `content/sources/*.yaml` — вони генеруються з реєстру
і будуть перезаписані. `sources/snapshots/` — це збережені копії законів.

## Три правила, які перевірка не пропустить

1. **Кожне твердження має джерело.** У файлі є поле `sourceIds` — id з реєстру
   джерел. Немає джерела — збірка впаде. Так і задумано.
2. **Українською і словацькою однаково.** Якщо додати текст лише в один мовний
   файл, збірка впаде. Обидві мови рівноправні.
3. **§ має існувати в законі.** Якщо написати `404/2011 §99`, перевірка звірить
   це зі збереженою копією закону і зупинить збірку.

## Статуси: хто що може ставити

- `draft` — чернетка;
- `source_verified` — дані взяті зі збереженої копії джерела (це **не** юридична
  перевірка);
- `legally_reviewed` — **ставить тільки юрист**, разом із полями `reviewer`
  (ім'я) і `reviewedAt` (дата). Без них збірка впаде;
- `published` — після перевірки.

Окремо у маршрутів є `conditionsComplete`. Поки він `false`, сайт ніколи не
скаже людині «підходить» — лише «варте уваги». Піднімати його можна тільки
тоді, коли перелік умов звірений із законом повністю.

## Як додати нову сторінку

1. Дописати пункт у `content/ui/site.yaml` (розділ `nav`).
2. Додати підпис у `nav` в обох мовних файлах.
3. Сказати розробнику, що потрібна сама сторінка — це вже код.

Без першого кроку сторінка працюватиме лише при переході всередині сайту, а
за прямим посиланням даватиме 404.

## Якщо щось зламалося

`git status` покаже змінені файли, `git diff` — що саме змінилося.
Повернути один файл до попереднього стану: `git checkout -- шлях/до/файлу`.
